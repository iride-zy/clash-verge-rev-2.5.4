# 节点网络信息

代理组的单列和多列节点卡片显示 UDP NAT Type、入口 IP/地理信息和出口 IP/地理信息。
点击原来的延迟测试按钮或批量测试按钮，会同时检测这些信息。首次使用更新后的应用时，需要正常加载运行配置。

## 实现边界

- 不修改 Mihomo 内核，不启动第二个内核，不切换用户正在使用的代理组。
- 配置增强阶段为原生节点和每个 provider 分别生成隐藏选择组、仅监听 `127.0.0.1` 的 mixed 入口。Mihomo 原生 `listeners.proxy` 将检测流量送入原节点对象，沿用节点的链式代理等配置。这些入口随主内核配置管理。
- DelayManager 复用单节点/批量触发、并发队列、缓存和通知；HTTP 与 UDP 检测在后端串行占用内部选择组，防止切换出口。延迟数值先更新，网络信息完成后更新。同一轮重复请求合并，运行配置代次改变后丢弃旧检测结果。
- provider 使用独立选择组，按 provider 名和原节点名定位。应用代理视图排除内部组。
- 入口 IP 从检测连接的 `metadata.remoteDestination` 读取，不将 DNS 解析结果当作实际连接地址。无法取得实际 IP 时显示未知。链式代理的入口含义以 Mihomo 返回的连接信息为准。
- HTTP 出口和入口地理信息通过当前检测节点访问 `https://api.ip.sb/geoip`；UDP 出口单独显示在提示信息中，不能假设 TCP 与 UDP 出口 IP 一定相同。
- NAT 检测通过同一个 SOCKS5 UDP 会话访问 `stunserver2025.stunprotocol.org:3478`，使用 RFC 5389/5780 的事务、映射地址及 CHANGE-REQUEST。过滤测试在访问备用地址之前执行，防止提前打开映射影响判断。
- 展示的是代理路径的 NAT 行为；服务器不支持 RFC 5780、检测超时、映射中途改变时返回未知。过滤请求重试后无响应仍可能受丢包影响，提示中明确说明。无法从代理会话证明“无 NAT”，不会将其误报为 Open Internet。
- 检测完成后关闭内部入口的连接，包括 Mihomo 内仍存在的 UDP 映射，避免后续节点复用。没有可用检测入口时仅检测失败，不回退到系统代理或直连。
